# Crossbid web app

Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · shadcn/ui.
Self-contained: nothing here needs the backend's toolchain (no Python, no `uv`).

## Quick start

```bash
npm install
npm run dev          # http://localhost:3000
```

Node 22 or newer. The API is a separate process on a separate origin — start it
from `backend/` (`uv run uvicorn crossbid.main:app --reload`, port 8000). The web
app talks to it over HTTP only; it never reaches the database, the LLM provider,
or any secret.

Today the app is the authenticated shell (S4.1.2) plus a public landing page.
Navigation reaches Dashboard, Company, Settings and New bid; each of those
screens shows an empty state that explains the next step. The screens themselves
— sign-in, the company profile and upload table, TED search, the bid workspace,
chat, and the developer console — arrive with stories S4.1.1–S4.6.4. There is no
authentication yet: `(app)` renders for anyone, and the redirect for a signed-out
visitor lands with S4.1.1.

## Tasks

| Command             | What it does                                              |
| ------------------- | --------------------------------------------------------- |
| `npm install`       | Install dependencies from `package-lock.json`             |
| `npm run dev`       | Dev server on :3000                                       |
| `npm run build`     | Production build (`output: "standalone"`)                 |
| `npm start`         | Serve the production build                                |
| `npm run lint`      | ESLint (`next/core-web-vitals`, `next/typescript`)        |
| `npm run typecheck` | `tsc --noEmit` — the check repo CI runs                   |
| `npm run gen:api`   | Regenerate `lib/api.ts` from the backend's OpenAPI schema |

From the repository root, `make dev`, `make lint` and `make deps` cover both apps.

## Generated API types

`lib/api.ts` is generated by [`openapi-typescript`](https://openapi-ts.dev) from
the live schema at `http://localhost:8000/openapi.json`:

```bash
# with the backend running on :8000
npm run gen:api
```

> **`lib/api.ts` is generated and never hand-edited.** Run the generator
> whenever a backend Pydantic model changes, and commit the result: CI
> regenerates it and fails the build if the committed file has drifted
> (S0.1.4 / S0.4.2). The backend's Pydantic models are the single schema source;
> this file is the only thing the two apps share.

The backend currently exposes only `GET /health`, so the file describes exactly
that one operation and the `Health` model. It grows with every router story; the
pipeline itself is done and the file is committed, which is what CI diffs
against. Generation is deterministic — two consecutive runs against the same
schema produce a byte-identical file.

### Calling the API

`lib/api-client.ts` is the hand-written counterpart: a thin `fetch` wrapper whose
method, path, query, body and response types all come from `lib/api.ts`, so a
route or field the backend does not expose does not compile here either.

```ts
import { apiRequest, ApiError } from '@/lib/api-client'

const health = await apiRequest('get', '/health') // { status: string; service: string }
const bid = await apiRequest('get', '/bids/{id}', { token, path: { id } }) // once that route exists
```

It attaches `Authorization: Bearer <token>`, never sends cookies, and turns any
non-2xx answer — or a transport failure, as `status === 0` — into an `ApiError`
carrying `status`, `method`, `url` and the parsed `{ detail }` payload. The base
URL comes from `NEXT_PUBLIC_API_URL` (inlined at build time), defaulting to
`http://localhost:8000`.

It stops there on purpose: the Supabase session, React hooks, the 2-second
`GET /bids/{id}` poll and multipart upload belong to their own stories (S4.1,
E4), so callers pass the token in explicitly for now.

## Layout

Folders appear as the stories that need them land (see `docs/project-plan.md` →
Repository layout). Today only these exist:

```
app/
  layout.tsx           root layout, fonts, metadata
  page.tsx             public landing page
  globals.css          Tailwind v4 + shadcn theme tokens
  (app)/               authenticated shell — header, nav, advisory-only footer
    layout.tsx
    dashboard/         first-run empty state (the bid list is S4.4.1)
    company/           placeholder (form S4.2.1, upload table S4.2.2)
    settings/          placeholder (language and tone S4.2.1, BYOK S4.6.4)
    bids/new/          placeholder (TED search to start is S4.3.1)
components/
  layout/              app header, main nav, mobile nav, footer, page header,
                       skip link, and NAV_ITEMS — the one nav definition
  common/              EmptyState
  ui/                  shadcn/ui primitives (button, card, sheet)
lib/           api.ts (generated), api-client.ts (typed fetch wrapper),
               utils.ts (shadcn `cn` re-export)
public/        static assets
```

The `(app)` route group adds no URL segment: `app/(app)/dashboard/page.tsx`
serves `/dashboard`.

Planned: `components/matrix/`, `components/pdf/`, `components/verdict/`,
`app/(auth)/login/`, `app/(app)/bids/[id]/`, `app/dev/` gated by
`is_developer`, `lib/supabase.ts`, and the bid-polling hook. None of them exist
yet — creating them ahead of their stories would be speculative, and the three
`components/` folders are additionally gated on the S4.0.1 design confirmation.

### Adding a section to the navigation

`components/layout/nav-items.ts` holds `NAV_ITEMS`. Both the desktop bar and the
mobile sheet iterate it, so a new section is one entry there plus the route
folder — the two can never drift. `isSectionActive` decides which entry gets
`aria-current="page"` and the tinted background.

## Adding shadcn/ui components

`components.json` is configured (style `radix-nova`, base colour neutral, Lucide
icons, CSS variables). Add a component when a story needs it:

```bash
npx shadcn@latest add button
```

`components/ui/` currently holds `button`, `card` and `sheet` — the shell's
primitives. They are ordinary source files (that is the point of
shadcn/ui) and are formatted to this repo's Prettier config, so re-adding one
with `--overwrite` produces a formatting diff until you run `npm run format`.

Note the S4.0.1 design gate in `docs/project-plan.md`: nothing under
`components/matrix/`, `components/pdf/` or `components/verdict/` may be coded
before the user confirms the design canvas. The shell, login and upload screens
are exempt because they are stock shadcn/ui.

## Configuration

No environment variables are needed for the scaffold. Once S4.1 lands the app
will read the Supabase URL, the Supabase anon key, and the API base URL from
`NEXT_PUBLIC_*` variables; copy `infra/.env.example` and keep secrets out of
anything `NEXT_PUBLIC_`-prefixed — the browser sees those.

## Docker

`Dockerfile` is a three-stage build (deps → build → runtime) on `node:22-alpine`,
using Next.js standalone output, running as the non-root user `crossbid`, with a
healthcheck on `/`. `infra/docker-compose.yml` builds it as the `web` service.
