## Verified external facts (2026-09-10)

These were checked against live endpoints; rely on them rather than re-deriving.

- **eCertis REST**: base `https://ec.europa.eu/growth/tools-databases/ecertisrest/`, GET only, no key. Spec v0.6 (2023). The model is criterion-centric (the 56 ESPD exclusion grounds and selection criteria), not certificate-centric: "equivalence" means the same EU criterion with different national evidence. Confirmed 2026-09-10: it does **not** map arbitrary standards — zero occurrences of ISO 27001 / 9001 / 14001 across the complete DE+FR payloads. Cached as JSON in the repo (`backend/crossbid/reference/data/ecertis/`, ~660 KB — the ~500 KB this said before predates the German localisation overlay), so run time never touches the network.

  Corrections from implementing S1.1.1 (ADR-0007) — the earlier notes were wrong in ways that matter:
  - **Never key anything on a national criterion id.** `criteria?nationalEntity=de` returns the same 56 criteria under *country-scoped* UUIDs, and the DE and FR sets are disjoint from each other and from the bare `criteria` set. The only cross-border identifier is the **EU-level UUID from the bare `GET criteria` call** — that is what `criteria.json` and the `EcertisCriterionId` Literal use. National ids live inside `evidence_*.json` as `sub_criteria[].id`, a separate id space with **zero** overlap with the EU ids.
  - `criteria/{uuid}?countryFilter=xx` **only works with an EU-level uuid**. Given a national uuid, `countryFilter` is silently ignored and you get that country's payload back regardless of what you asked for.
  - The model is **three levels deep, not two**: criterion → national `sub_criteria` → `RequirementGroup` (these are *alternatives*, "any one of these papers") → `TypeOfEvidence`. The group layer carries real meaning and is preserved in the cache.
  - **HTTP 200 with an empty body is a valid answer meaning "this country has no national entry"** — 17 of 56 criteria for FR, 1 of 56 for DE. Transient emptiness also happens and is indistinguishable at the wire level, so the client retries 3× with backoff and refuses to overwrite a cached criterion that previously had evidence and now has none.
  - `GET criteria` omits `CriteriaTypeName`, sending only a meaningless `CriteriaTypeID`, so the bare list cannot distinguish an exclusion ground from a selection criterion. The taxonomy is stitched in from one extra `criteria?nationalEntity=eu` call (labels are byte-identical across countries). `nationalEntity=eu` returns 58 rows, not 56.
  - Undocumented `?lang=de` returns German, marked `(Automatische Übersetzung)`. `languageID`, `language`, `languageFilter` and `Accept-Language` are all ignored. This is the cheap route to S1.1.2's bilingual requirement; not cached.
- **TED Search API v3**: `POST https://api.ted.europa.eu/v3/notices/search`, no key. Expert query syntax; `IN (...)` does not accept `OR` inside the parentheses. Useful returnable fields: `document-url-lot`, `official-language`, `submission-language`, `selection-criterion-description-lot`, `deadline-receipt-tender-date-lot`, `links` (notice XML/PDF/HTML in all 24 languages). `document-url-lot` points to national platform HTML pages (TenderNed, Vergabemarktplatz, eb2b, ezamowienia), so procurement documents cannot be fetched automatically under the no-scraping rule; the user uploads them.

  Corrections and additions from ~1 000 live queries on 2026-09-10 (DE, FR, EN samples):
  - `SORT BY publication-date ASC` returns **HTTP 400**. Only `DESC` works.
  - Pagination caps at **600 results** — `limit=100, page=7` is HTTP 400 even when `totalNoticeCount` is higher. Narrow the query rather than paging past it.
  - `selection-criterion-description-lot` is **much sparser than assumed**: populated on 14% of French and 17% of English CPV-72 notices; 496 of 600 English notices had none. Notices routinely answer "Sources: Procurement Document" for both criteria fields. This is the strongest evidence for the upload-the-pack design — the notice usually does not carry the requirements.
  - `links` also exposes `links.pdfs.<official-language>` and `links.htmlDirect.<LANG>` alongside `links.pdf.<LANG>`.

  Re-probed live on 2026-09-14, before S1.2.1 starts. The endpoint is up and these four facts
  are what the story has to build against:
  - **A CPV value must be the full eight digits.** `classification-cpv IN (72)` is HTTP 400
    `QUERY_UNSUPPORTED_FIELD_VALUE`; `IN (72000000)` works and matches 398 133 notices.
  - **Sorting lives inside the query string, not beside it.** A JSON `"sort"` field is rejected
    outright (`Unrecognized field "sort"`); it is `... SORT BY publication-date DESC` appended
    to `query`. (`DESC` only — `ASC` is 400, as recorded above.)
  - **`deadline-receipt-tender-date-lot` is a list, one entry per lot, and carries a DATE with
    an offset and no time of day.** Example: `['2026-10-07+02:00']`. Across 58 lot deadlines in
    a fresh CPV-72 sample, **zero carried a time component**; offsets seen were `+02:00`,
    `+03:00`, `+01:00` and bare `Z`. So TED can fill `bids.deadline_utc_offset_minutes`
    (migration 0007) but **cannot fill the hour** — only the notice PDF or the bidder can, which
    is why the start form takes a date *and* a time (S4.4.1). Most notices have one lot; up to
    four were seen.
  - **Fill rate depends entirely on the notice type.** 44 % of a mixed sample carried a
    deadline, but that is an artefact: `can-standard` award notices have none by nature. Among
    **`cn-standard` contract notices — the ones a bidder acts on — it is 84 %.** Filter on
    notice type before quoting a coverage figure.
  - **`buyer-name` is a language-keyed dict of lists**, e.g.
    `{'spa': ['Dirección General de Racionalización…']}`, not a string. `bids.buyer` is plain
    text, so S1.2.1 has to choose a language rather than assume one.
  - **No German or French CPV-72 notice sampled hosts its documents on TED.** The EU Funding & Tenders Portal (EU institutions and agencies, notices in English) is the only platform found that serves procurement documents as plain unauthenticated `GET` URLs, including a download-all zip. Its JSON APIs are not usable — `api.sedia-backoffice-production.eu/.../{uuid}-CN` is 403 and `api.tech.ec.europa.eu/search-api` does not index tender records.
- **ESPD / DUME XML is the bridge to eCertis, confirmed on real data.** A French buyer's `DUME_acheteur.xml` (committed in the FR fixture) declares 30 `ccv:Criterion` elements carrying the canonical ESPD criterion UUIDs — e.g. `499efc97-2ac1-4af2-9e84-323c2ca67747` "Chiffre d'affaires annuel général", `1f49b3f0-d50f-43f6-8b30-4bafab108b9b` "Effectifs moyens annuels". These are the same ids eCertis is keyed on, so where a tender publishes a DUME the criterion mapping needs no LLM inference at all. Treat a published DUME as a high-confidence structured input, not as prose to extract.
- **LLM provider is OpenRouter only** (the user holds no OpenAI or Anthropic key). Verified 2026-09-10 against `https://openrouter.ai/api/v1/models`: `openai/gpt-5.6-terra` ($2/$12 per 1M) and `openai/gpt-5.6-luna` ($0.20/$1.20) support `structured_outputs`, `response_format`, and `tools`; For the eval judge and the multi-model demo, **`anthropic/claude-sonnet-5` is NOT available on this account** (HTTP 404). Re-probed with live calls 2026-09-10 — the account's data policy filters most providers. The non-OpenAI models that actually answer are `anthropic/claude-haiku-4.5` ($1/$5, the eval judge), `google/gemini-2.5-flash` ($0.30/$2.50) and `google/gemini-2.5-flash-lite` ($0.10/$0.40). Also 404: `claude-opus-5`, `claude-sonnet-4.5`, `gemini-2.5-pro`, `deepseek-chat-v3.1`, `llama-4-maverick`, `qwen3-235b`, `mistral-medium-3.1`, `nova-pro-v1`, `command-a`. **Presence in `/models` does not mean usable — always probe with a live call** (ADR-0005). OpenRouter's `/api/v1/embeddings`, probed 2026-09-10, serves exactly three usable embeddings on this account: **`openai/text-embedding-3-small` (1536 dims, ~$0.027/1M) — the default**, `openai/text-embedding-3-large` (3072 dims, $0.13/1M) as the quality switch, and `qwen/qwen3-embedding-8b` (4096 dims, ~$0.057/1M) as the non-OpenAI multilingual option. 3-small is the default because 1536 dims is under pgvector's 2000-dim index cap (ADR-0004). `baai/bge-m3`, `google/gemini-embedding-001` and `openai/text-embedding-ada-002` return **HTTP 404** on this account's data policy; Cohere, Voyage, Mistral, Jina and Nomic embeddings do not exist on OpenRouter at all. There is no `/models` listing for embeddings — probe the endpoint. `gpt-4o` is legacy. Use `ChatOpenAI(base_url="https://openrouter.ai/api/v1")` with `extra_body={"usage": {"include": true}}` for per-response cost. Keep slugs in `backend/settings.default.yaml`; never hard-code a model name. **Every company runs on its own OpenRouter key (S5.4, ADR-0091).** Stored per company in `provider_keys`, Fernet-encrypted, last-4 hint only, verified against the provider on save, never logged and never returned. **Embeddings use it too** — that reverses the earlier "embeddings always use the app's OpenRouter route" rule — so a company with no key saved cannot upload a document or start a bid: the API answers **402**, and never falls back to the application key. `OPENROUTER_API_KEY` in the environment is now operator tooling only (`make eval`, the judge, the scripts, the startup slug probe). Direct OpenAI/Anthropic keys are refused on save: every configured slug is an OpenRouter slug, so such a key would have nothing to call.
- **Supabase + LangGraph Postgres checkpointer/Store**: the transaction pooler does not support prepared statements. Use the direct connection locally and the session pooler in deployment. Measured on the project 2026-09-10: `max_connections=60`, 3 reserved, **12 sessions held by Supabase's own services before we connect** — `crossbid/db.py` pins these and sizes the one shared pool from them (ADR-0010). Verified in langgraph-checkpoint-postgres 3.1.2: **`AsyncPostgresSaver` serialises every operation on one `asyncio.Lock` even with a pool** (checkpoint throughput does not scale with pool size); `AsyncPostgresStore` does not; `store_vectors` is only created when an `index` config is passed. Both `.setup()`s are idempotent and run at API startup under an advisory lock — `scripts/migrate.py` never touches them.
- **Docling** supports `do_ocr=False`; OCR engines are Tesseract, EasyOCR, RapidOCR, ocrmac. **Frankfurter** (`api.frankfurter.dev`) serves ECB reference rates without a key.
- **Library behaviour learned the hard way (2026-09-10), all verified in this repo:**
  - `pymupdf4llm.to_markdown(..., page_chunks=True)` returns **`"\n\n\n\n"`, not `""`**, for a page with no text layer. An emptiness check written as `text != ""` calls an image-only page readable and emits a chunk of whitespace. Always test with `.strip()`; `ingestion.parser.has_extractable_text` is the one shared definition of "not read". `to_markdown` also raises `IndexError` on a zero-page document.
  - The markdown `to_markdown` returns is ~1.3% longer than `page.get_text()` (456 911 vs 451 088 characters on the DE pack) because it keeps headings and table structure. Both figures are correct; know which one a number refers to.
  - `tiktoken.get_encoding` **downloads its BPE table on first use** (~2 s, cached under `$TMPDIR/data-gym-cache`), so anything calling it is not offline. Inject the encoder in tested code paths. `tiktoken.encoding_for_model` raises `KeyError` on an OpenRouter slug such as `openai/gpt-5.6-terra` — there is no authoritative chat encoding, so `cl100k_base` is pinned by name. It is exact for `openai/text-embedding-3-small`, which is the consumer with a hard limit, and it over-counts German against the chat models (21 tokens where `o200k_base` needs 17), which is the safe direction for a budget.
  - `ChatOpenAI` under langchain-openai 1.6.2 **rejects `max_tokens=` as a keyword**; the accepted alias is `max_completion_tokens=` (it still populates `.max_tokens`).
  - LangSmith reads **four** tracing flags — `LANGSMITH_TRACING`, `LANGSMITH_TRACING_V2`, `LANGCHAIN_TRACING`, `LANGCHAIN_TRACING_V2` — and `tracing_is_enabled()` prefers the `_V2` and `LANGSMITH_` names. Writing only one lets a stale value of another win, so `configure_tracing` writes all four and clears `langsmith.utils.get_env_var`'s `lru_cache`. Do not set these by hand in `.env`.
  - psycopg_pool 3.3 **deprecates opening an async pool in the constructor** (`RuntimeWarning`); construct with `open=False`, then `await pool.open(wait=True, timeout=...)`. A typed pool is `AsyncConnectionPool(dsn, connection_class=AsyncConnection[DictRow], kwargs={"row_factory": dict_row, ...})` — the type parameter otherwise defaults to `TupleRow` and pyright rejects the assignment.
  - pgvector 0.5's psycopg adapter returns a **`Vector` object that is not iterable**: use `.to_list()`. Getting a `Vector` back at all (rather than a string) is the proof that `register_vector_async` ran on that connection.
  - Async tests use **`@pytest.mark.anyio`** — the `anyio` pytest plugin ships with the existing dependency tree, and `tests/conftest.py` pins `anyio_backend` to `asyncio`. Do not add `pytest-asyncio`.
  - **LangGraph reads the *string* of a node's `config` annotation.** Under `from __future__ import annotations`, `config: RunnableConfig | None = None` matches nothing on its accept-list, so the graph emits a `UserWarning` and **never injects the config** — silently, because the default keeps the call working. Spell it `Optional[RunnableConfig]` with `# noqa: UP045`; `tests/unit/test_extract_reqs.py` compiles a real graph with warnings promoted to errors to pin it.
  - **`datetime.fromisoformat` cannot read a date with an offset and no time, and fails
    silently.** TED publishes deadlines as `'2026-10-07+02:00'`; Python returns
    `datetime(2026, 10, 7, 2, 0)` with **no tzinfo** — the offset has been read as the hour,
    `utcoffset()` is `None`, and the zone is lost with no error. The date survives by luck,
    which is what hides it. Parse the shape yourself (`ted_client._date_and_offset`); the
    stdlib is only correct once a time component is present.
  - `pymupdf4llm` renders emphasis as markdown (`**Umsatz**`), and SP.1 read `page.get_text()` instead. A strict-substring "verbatim quote" check therefore rejects honest quotes whenever the clause carries a bold word; `extract_reqs._normalised` strips inline `*_\`` runs on both sides before comparing (whitespace collapsed, case never folded).
  - pgvector's psycopg adapter registers dumpers for **`pgvector.Vector` and `numpy.ndarray` only, never a plain `list`** — a `list[float]` parameter is sent as a Postgres array and rejected by a `vector` column. Bind `Vector(...)`; it narrows to float32, which is what the column stores. Bind a chunk's `pages` as a `list`, not a `tuple`: psycopg adapts a tuple to a composite record.
  - psycopg's `execute` / `executemany` are typed on **`LiteralString`**, so pyright refuses a query assembled at run time — a free guard that no code path can build an unscoped `WHERE`. Keep SQL as `Final[LiteralString]` module constants.
  - `storage3` (supabase 2.31.0): import `StorageException` from `storage3.utils`, not `storage3.exceptions` (pyright `reportPrivateImportUsage`). `create_client(url, key)` makes **no network call and never parses the key**, so the newer `sb_secret_…` keys and the legacy service-role JWT are indistinguishable to it — both work. `create_signed_url` returns both `signedURL` and `signedUrl`.
  - The DE fixture is **191 pages across the 28 files in `de/documents/`**, and **202** if the notice PDF one level up is included. A story that globs `de/**/*.pdf` gets a different number from one that globs `de/documents/*.pdf`.
